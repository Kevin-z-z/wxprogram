# 课时管理与打卡系统前端骨架

微信小程序原生前端，使用 WXML、WXSS、JavaScript 和 JSON。无需安装 npm 依赖。管理员端暂未实现。

## 运行方式

1. 打开微信开发者工具，导入本文件夹，项目类型选择小程序。
2. 使用自己的小程序 AppID；配置中的 touristappid 仅用于工具支持的游客体验，能力可能受限。
3. 编译后，在登录页选择家长或教师身份。首页可以切换身份，数据在本机保留。
4. 相机与定位需在支持的设备和项目配置下授权后体验；普通签到不依赖这些能力。

## 页面结构

pages/login 演示身份选择；parent 家长首页；teacher 教师首页；courses 课程目录；schedule 课表；session 课次及教师点名；checkin 三种打卡；leave 请假申请；leaves 请假记录及审批；hours 课时明细；orders 订单与退款查询；messages 站内消息。

services/store.js 是可替换的本地模拟服务，utils/page.js 提供页面身份检查、跳转及错误提示，components/nav 是按角色展示的底部导航。

## 推荐演示流程

1. 教师登录，进入第一节美术课，发布普通签到，活动开放 30 分钟。
2. 切换家长，在同一课次完成打卡；再次进入可查看结果，不重复记录。
3. 家长在两天后的美术课申请请假，教师切换到请假审批并批准。
4. 教师在第一节课将其他学生点名为出勤或缺席，填写人工修改原因，然后确认消课。
5. 家长查看美术余额从 10 变为 8，并在课时明细中看到扣减。重复结算不会再次扣减。
6. 需要重新演示时，切换身份回登录页，点击恢复初始演示数据。排课日期在重置时按当天生成。

## 本期规则

- 出勤按课次设定课时扣减，批准请假和缺席不扣；待点名和待审批未完成时不能结算。
- 课时不足时保留考勤，暂停本次结算；不产生负余额。
- 一名学生一个课次一条签到记录。请假须在该课次开始前提交。
- 教师仅演示管理美术班；家长绑定学生小禾。教师只能通过审批产生请假考勤。
- 结算后考勤只读，补扣、返还和考勤更正流程尚未实现。
- 教师发布位置活动时，以教师当前位置作为签到中心，半径 200 米；拍照活动只允许现场拍摄。

## 接入后端时必须替换

身份选择只是演示开关，不能用于真实登录。全部数据保存在 wx 本地存储，清除缓存后丢失；不同设备间不共享。页面和模拟服务的角色限制均可被客户端篡改，真实后端须独立校验登录、角色、学生绑定与任课关系。

消课需要后端事务与唯一约束保障；本地一次保存仅适合交互演示。签到时间和距离应由后端校验，不能信任客户端时间、坐标或角色字段。

照片当前仅保存临时文件路径，重启后可能失效；后续应上传私有存储并按权限读取。位置与相机能力需按实际小程序主体、隐私声明、接口权限及真机情况配置验证。

本版本不包含真实支付、退款处理、微信订阅通知、管理员维护、课后更正及自动排课。消息均为本地站内演示。

## 验证范围

已提供无第三方依赖的模拟服务测试 scripts/store.test.js，可用 Node.js 运行；仅验证模拟数据层的重复签到、审批、课时结算和权限限制，不能替代微信开发者工具编译与真机测试。


已修复 WXSS 通配选择器与 WXML 条件转义导致的编译错误。使用微信开发者工具自带编译器验证全部 13 个 WXML 和 14 个 WXSS 文件通过，工具热重载后登录页正常显示且错误数为零。

编译回归检查：node scripts/compile.test.js <包含wcc.exe和wcsc.exe的目录>。该脚本调用真实小程序编译器，补充通用 JavaScript 和 XML 检查无法覆盖的规则。
